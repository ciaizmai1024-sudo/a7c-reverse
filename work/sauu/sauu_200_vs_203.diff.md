# `sauu` 2.00 vs 2.03 差分（2025-10-24，E0 静态）

两份文件（同大小 84,428 B，同节表，ET_EXEC ARM32 Thumb-2，vaddr = file_off + 0x8000）：

```
2.00 机身 a1 : work/l1-camera/a1_initrd/usr/bin/sauu   sha256 5e345c865f96675d…
2.03 包  a1 : work/v203/a1_initrd/usr/bin/sauu        sha256 d79af0e6958e47c9…
节布局相同：.plt 0xb450-0xbb90, .text 0xbb90-0x15710, .rodata 0x15718-0x195e4,
             .ARM.extab 0x195e4, .ARM.exidx 0x1af54, LOAD0 off0/vaddr0x8000 fsz0x13ea4,
             LOAD1 off0x14000/vaddr0x24000
```

## A. 汇总

| 项 | 结果 |
|---|---|
| `cmp -l` 总差异字节 | 5,924（含非 .text） |
| `.text` 差异 | 4,583 B，分布在 **569 个块**，范围 **vaddr 0xe64e → 0x14ca1**；`0xbb90-0xe64d` **完全相同** |
| `.dynstr` / `.dynsym` | 610 / 39 B 差异，但 **符号名字集合完全相同**（同一批名字换了顺序 ⇒ `.gnu.hash`/哈希桶抖动的连带结果，非新增导入） |
| `.rodata` | 256 B（字串池/跳转表随代码平移） |
| `.ARM.extab` / `.ARM.exidx` | 150 / 285 B（异常表随代码平移） |
| `.dynamic` | 1 B |
| 函数数量（r2 `aaa`） | **两版都是 457 个** |
| 0xe7xx 之后函数地址 | 2.03 相对 2.00 **整体 +0x120**（例：2.00 `0xe73c` ↔ 2.03 `0xe85c`）⇒ 该区域前插入了 ~288 B 代码 |
| **PLT 表（stub→import）** | **151 条逐条完全相同**（`work/sauu/elfplt.py` 两版输出 `diff` 无差异） |

## B. 验签相关代码：**逐字节相同**（决定 2.03 没有新增验签、也没有加旗标 gate）

对 2.00 与 2.03 直接按 vaddr→off 比对（`v2o(v)=v-0x8000`）：

| 区域 | 函数 | 结果 |
|---|---|---|
| 0x10368-0x104b0 | `fcn.00010368` = `SignatureVerification` 的 "verifyKey"（open/lseek/mmap + SHA1 + MWF IPC + strncmp） | **same=True, ndiff=0** |
| 0x104e0-0x105a4 | `fcn.000104e0` = `VerifySignature`（fopen/PEM_read_RSA_PUBKEY/SHA256/**RSA_verify@0x10568**/RSA_free） | **same=True, ndiff=0** |
| 0x10a88-0x10c40 | `UFPDecryptorModule::virtual_60`（组 `verify_info`、**调用点 0x10b0e**、`"Signature Verification Error"` + throw 0x30002） | **same=True, ndiff=0** |
| 0x10948-0x10990 | `UpdaterManager.virtual_8` ctor（把 vtable 设成 UFPDecryptorModule、`Dec_ScrambleInit`） | **same=True, ndiff=0** |
| 0xbb90-0xc000 | `.text` 头部（启动/PLT 胶水） | **same=True, ndiff=0** |

两版里这些调用点地址也一模一样（r2 `aaa; axt`）：

```
RSA_verify            stub 0xb60c  ← 0x10568   (fcn.000104e0)
PEM_read_RSA_PUBKEY   stub 0xbb84  ← 0x1053c
SHA256                stub 0xb940  ← 0x10554
RSA_free              stub 0xbae4  ← 0x1058a
SHA1_Init/Update/Final 0x103de/0x103e8/0x103f2 (fcn.00010368)
VerifySignature 的调用点      0x10b0e  (thunk 0x10d00 `b.w 0x10a88`)
virtual_60 的间接派发点        0x138a6 `ldr r3,[r3,0x3c]; blx r3` (fcn.0001383a = virtual_12)
```
⇒ 就 `sauu` 本身而言：**2.03 既没有新增验签调用点，也没有加旗标 gate**；两版的 USER/SERVICE 路径结构一致。

## C. 真正的语义差异（mmap / 缓冲尺寸掩码）

第一个 .text 差异点 **0xe64e**，落在 `method.Updater::BufferManager.virtual_8`（0xe628 起）：

```
                2.00                                  2.03
0x0000e646  c0f10005  rsb.w r5, r0, 0            c0f10005  rsb.w r5, r0, 0     ; r0 = sysconf(_SC_PAGESIZE)
0x0000e64a  8046      mov r8, r0                 8046      mov r8, r0
0x0000e64c  05f00055  and r5, r5, 0x20000000     05f08045  and r5, r5, 0x40000000   ★ 掩码翻倍 512M→1G
0x0000e650  3046      mov r0, r6                 3046      mov r0, r6
0x0000e652  2946      mov r1, r5                 2946      mov r1, r5
0x0000e654  fdf770e8  blx sym.imp.mmap          fdf770e8  blx sym.imp.mmap
```

这与旧文档 `SIG_VERIFY_200.md` §B 在 `libsdfileinputupdaterapi.so` 里发现的改动属同一族
（那边是 `BufferManager::Initialize` 的 `sysconf(30)/mmap` 指令 4 字节改动）：
**2.03 把 body 缓冲的可映射长度上限放大（掩码 0x20000000 → 0x40000000）**，与 crypto 无关。

其余 560+ 个小块 = 该掩码改动引发的指令位移 + 字串池/跳转表重排 + `.ARM.exidx/extab` 重编码；
没有发现新增函数、没有发现新的条件分支包裹验签。

## D. 与 `IAMSIGNENABLED` 有关的部分（不在 `sauu` 里）

* 两版 `sauu` 都 **0** 命中 `IAMSIGNENABLED`（`strings -a` + `.rodata` 全扫）。
* 唯一含该字串的**代码**：`work/v203/a1_initrd/usr/lib/libupdater0604.so`（2.03）
  的 `sym.udtr_adjcmd_get_verifysign`（字串 xref 0x2d54 / 0x2d60）：
  `/tmp_updater/root/IAMSIGNENABLED`、`/tmp_updater/root/IAMSIGNDISABLED`、
  `[UDTR0604] UD_GET_VERIFY_SIGN can not mount %s: (ret = %d)`、`… can not mount cramfs`、
  `… can not stat sign marker file`，另有 `/mnt/boot/initrd.img`、`/tmp_updater`。
* 2.00 机身的 `libupdater0604.so` **不含任何 `IAMSIGN*` 字串**（两版该库仅差少量字节，2.03 多出整段命令处理）。
* 2.03 a1 initrd 里**真的存在**该旗标文件：`work/v203/a1_initrd_manifest.tsv` 有
  `/root/IAMSIGNENABLED  0  e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`（空文件）；
  2.00 机身 a1 的 manifest 只有 `/root/IAMUPDATER`，无 `IAMSIGN*`。
* 该查询命令的**调用者未知**（离线树里除 `libupdater0604.so` 自身、`mf`、`ud_im.elf` 对库名的引用外无别的引用）
  ⇒ 只到"存在该读数命令"的 E0 弱级；不能据此断言"2.03 运行时的验签由这个旗标开关控制"。
