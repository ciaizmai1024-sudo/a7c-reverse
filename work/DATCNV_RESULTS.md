# ud_datcnv.elf 离线验证结论（dat2/dat3/dat4 编码格式）— 实测【已验证】

日期：用相机自己的 ARM32 ELF 在 docker(debian:buster-slim, --platform linux/arm/v7) 里实跑。
脚本：`work/t_datcnv.sh` ~ `work/t_datcnv5.sh`，入口 `work/datcnv_run.sh`。
仓库原有文件未改动。

## 0. 怎么跑（可复用的命令）

```
docker run --rm --platform linux/arm/v7 \
  -v "$PWD/firmware.tar_unpacked/0700_part_image/dev/nflasha7_unpacked":/cam:ro \
  -v "$PWD/firmware.tar_unpacked/0700_part_image/dev/nflasha15_unpacked":/u:ro \
  -v "$PWD/work":/w -w /w debian:buster-slim sh /w/t_datcnv.sh
```
容器内（见脚本头部）：`cp -r /cam /c; chmod -R +x /c/lib;` 补 glibc 符号链接（同 tools/camprefix.sh），
再把 `/u/lib/libstdc++.so.6.0.14`、`/u/lib/libosal_uipc.so` 拷进 `/c/lib`（nflasha15 没有 glibc，nflasha7 没有 libstdc++），然后：
```
L=/c/lib/ld-2.11.2.so
$L --library-path /c/lib /u/bin/ud_datcnv.elf -e -i in.txt -o out.bin -a
```
唯一噪音：`open /dev/uipc error: : No such file or directory`（libosal_uipc 的构造函数找不到 /dev/uipc，无害，rc 不受影响）。

## 1. 命令行/usage

- 全部只读字符串（.rodata 只有 20 字节）：optstring `ahvedi:o:`、`rb`、`w+`。
- **没有任何 usage/help 文本**：`-h`、`-v` 被 getopt 接受但什么都不打印（rc=0）。
- 未知选项：`ud_datcnv.elf: invalid option -- 'x'`，rc=1。
- 退出码：0=成功；1=非法选项；2=`-e` 打不开输入/输入为空(0 字节)；3=`-d` 输入为空/打不开。
- 同时给 `-e -d` → rc=1，不写输出。

## 2. `-a` = ASCII/BCD 文本模式（dat2/3/4 用的就是这个）

**编码 -e -a**（文本 → dat）：
1. 每个字符取 **低半字节** `nib = c & 0x0F`（数字 '0'-'9'→0-9；'.'=0x2E→0xE；字母 'A'→0xA…全部按低 4 位，无校验/无查表）。
2. 若字符数为奇数，**丢弃最后一个字符**（所以 `echo "2.00"` 的换行 0x0A 被丢掉 → 与不带换行结果相同【实测 cmp 相同】）。
3. 按原文顺序两个字符一组：`byte = (nib[2i]<<4)|nib[2i+1]`（前一个字符是高半字节）→ 得到大端 BCD 串。
4. **字节序反转**（写成小端）。输出长度 = `floor(L/2)` 字节，**无 magic、无头部、无长度字段、无校验字节**，也不补到固定长度。

实测（`od -An -tx1`）：
```
"0200"   -> 00 02        "0100" -> 00 01      "0000" -> 00 00
"2.00"   -> 00 2e        ("2.00" 带换行 -> 同样 00 2e；带 \r\n -> da 00 02)
"91030019" -> 19 00 03 91   "00000000" -> 00 00 00 00   "65535" -> 53 65
"0123456789" -> 89 67 45 23 01
```
**手工构造 == 工具产物**（用 `printf` 八进制，dash 下 `\xNN` 不认）：
```
printf '\000\001'        == 工具编 "0100"     ✓
printf '\000\056'        == 工具编 "2.00"     ✓
printf '\031\000\003\221'== 工具编 "91030019" ✓ (= 19 00 03 91)
```
公式：文本 d0..d(L-1) → `文件字节[j] = ((nib[L-1-2j]<<4) | nib[L-2-2j])`，j=0..floor(L/2)-1。
即「先按两字符打包成 BCD，再小端存放」。

**解码 -d -a**（dat → 文本）：从**最后一个字节**往前，每字节输出 `hi+0x30`、`lo+0x30`，最后追加 `'\n'`。
输出文件长度 = `2*输入字节数 + 1`。半字节>9 时用 `+0x30` 直接出字符（0xE→'>'，0xF→'?'），不做合法性检查。

## 3. 不带 `-a` = 另一种模式（**不是**“同一算法去掉 ASCII 层”，而且不对称）

- `-d`（无 -a）：**纯字节逆序**，长度不变（输入 11 12 13 14 → 输出 14 13 12 11）。
- `-e`（无 -a）：输入 L 字节 → 输出 L（L 偶）或 L-1（L 奇）字节；`out[0]=0x00`，其后是 `in[L-1]…in[1]`（L 偶）/ `in[L-2]…in[1]`（L 奇）。
  例：`01 02 03 04` → `00 04 03 02`；`A1 B2 C3 D4` → `00 D4 C3 B2`；`01 02 03` → `00 02`；单字节 → 0 字节。
- 所以无 -a 的 `-e`/`-d` **互不互逆**：`"0200"` → 编 `00 30 30 32` → 解 `32 30 30 00` = `"200\0"`。
- 结论：`-a` 的真正作用就是「把 dat 当 2 字符/字节的 ASCII 半字节文本处理」；up.sh 读回文本再 cat，用的必然是 `-a`。

## 4. 校验/防篡改：**没有**

- 把 `00 02`（"0200"）改成 `ff 02` → `-d -a` rc=0，得 `[02??]`；改成 `5c 02` → `[025<]`。改任意字节都不报错，只是解出不同文本。
- 截短到 1 字节也能解（→ `00`）；**空文件** `-d` → rc=3，不产生输出文件。
- 长度限制（唯一硬约束）：**输入 > 8 字节 → rc=0 但输出 0 字节（静默失败，危险）**；
  编码侧 **> 16 个字符** 同样 rc=0 但写出 0 字节文件；16 字符→8 字节 OK，17 字符→空。
  解码侧 16 字节→33 字符 OK，17 字节→空文件。即工具内部缓冲只支持 **8 字节 / 16 字符**。
  对 dat2/dat3/dat4（4/4/2 字节）完全够用（up.sh 也强制 modmod/modreg 参数 8 字符、modver 4 字符）。

## 5. 与 FDAT 头对照（可用来伪造 dat2）

FDAT 头 `+36 model=0x91030019`（文件里字节序 `19 00 03 91`）**正好等于** dat2 的 `-e -a` 产物：
文本 `"91030019"` → `19 00 03 91`（= 小端 u32 0x91030019）。region `"00000000"` → `00 00 00 00`。
所以 dat2 = 头字段同编码，直接 `printf '\031\000\003\221' > dat2` 就是合法文件。

**注意点（重要）**：`-a` 模式下 `'.'` 不是十进制点，而是半字节 0xE：
`"2.00"` → `00 2e`，但再 `-d -a` 解回是 **`"2>00"`**（不往返！）。
所以若 up.sh 的 read-modify-write 逻辑成立，相机里 dat4 存的版本文本不可能字面含 `.`，
更像是 `"0200"`（→ `00 02`，往返一致）。版本 2.00 在 FDAT 头里是另一个字段，不能直接照搬 `"2.00"`。

## 6. 能否自己生成合法 dat？能。

```sh
# dat4 版本 "0200"（4 字符 -> 2 字节 LE BCD）
printf '\000\002' > dat4
# dat2 机型 91030019（8 字符 -> 4 字节）
printf '\031\000\003\221' > dat2
# dat3 region 0
printf '\000\000\000\000' > dat3
# 验证（离线，本仓库工具）：
docker ... -d -i dat4 -o out.txt -a   # -> "0200\n"
```
用 `echo 0200 | ...` 的换行会被奇数位丢弃逻辑自动忽略，与 up.sh 行为一致。
