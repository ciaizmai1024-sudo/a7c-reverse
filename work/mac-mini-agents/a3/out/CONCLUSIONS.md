## 4. SSBOOT.BIN / SSBOOT_ANY.BIN 是什么

### 4.1 文件事实

| | ssboot.bin | ssboot_any.bin |
|---|---|---|
| 路径 | `/sabin/ssboot.bin` | `/sabin/ssboot_any.bin` |
| 起始簇 | 1254 | 1255 |
| 字节偏移 | `0x139C200` (20,562,432) | `0x13A0200` (20,578,816) |
| 大小 | 11,280 | 9,648 |
| MD5 | `0fb03e483e4e437111888265e1999900` | `f8ec8bb13e1efa7d010f222570fa8ef9` |
| SHA1 | `76a0740394237131418eb4638f55afe7a4ab34a3` | `eccfffdf1fc8aa3c15a5bd87a538b745872471de` |
| 熵 | 6.324 bit/byte | 6.353 bit/byte |
| 0x00 占比 | 19.31% | 18.59% |
| 0xFF 占比 | 4.04% | 4.60% |
| 头部长度 | `0x80` | `0x7C` |
| 载荷起点 | `0x80` | `0x7C` |

两者都是**单簇连续存放**（1 个 16 KiB 簇），不存在跨簇链。

### 4.3 结论：私有 “B4” 容器，不是通用可执行格式

两个文件共享同一个容器头：

- 偏移 `+0x04` 处固定为 ASCII `42 34` = **“B4”**（`+0x06/+0x07` 是长度字段，ssboot 为 `0x004F`，ssboot_any 为 `0x000F`）。
- `+0x00` 起为 `3d 00 3f b0` / `3d 00 3d b0`，不是任何已知文件系统/固件魔数。
- `+0x2C` 固定为 `0x00000682`（1666），三个同族文件完全一致。
- `+0x40/+0x44/+0x48` 为 `0x1800/0x2800/0x3800`，像三段大小/间距。
- `+0x54` 起是一串 32 位指针，全部落在 `0x48000–0x49E00`，说明该镜像按基址 **`0x48000`** 装载，头内是镜像内偏移而非文件偏移。
- `+0x68` 固定出现 IEEE-754 浮点 `0x3FF80000` = **1.9375**。
- `+0x08` 分别为 `0x10080001` / `0x10080005`，`+0x0C` 分别为 `0x2C10` / `0x25B0`：更像变体号 + 载荷长度，而不是版本字符串。

关键字段对照（同目录 `idt_cam.bin` 作参照）：

| 偏移 | ssboot | ssboot_any | idt_cam | 说明 |
|---|---|---|---|---|
| +0x00 | `b03f003d` | `b03d003d` | `b03b003d` | 头标识，末两字节递增/递减 |
| +0x04 | `004f3442` | `000f3442` | `001f3442` | **“B4”** + 长度 |
| +0x08 | `10080001` | `10080005` | `20000004` | 推测类型/变体 |
| +0x0C | `00002c10` | `000025b0` | `00000910` | 与载荷长度相关 |
| +0x2C | `00000682` | `00000682` | `00000682` | 家族常量 1666 |
| +0x40/44/48 | `1800/2800/3800` | `1800/2800/3800` | `2000/4000/6000` | 分段大小 |
| +0x54..78 | 指向 `0x48000–0x49E00` | 同左 | 同左 | 镜像内指针表 |
| +0x68 | `3ff80000` | `3ff80000` | `3ff80000` | 浮点 1.9375 |
| 入口 | `0x80` | `0x7C` | `0x7C` | 载荷起点 |

`ssboot.bin` 比 `ssboot_any.bin` 多一个 `0x49E00` 指针，头部因此长 4 字节（`0x80` vs `0x7C`）。

### 4.4 无版本串

- 对全部内容做 ASCII 与 UTF-16LE 扫描，没有任何 ≥8 字节的可打印字符串；仅有的片段是 `&$kq'${y`、`)wit`、`# 9r` 这类二进制巧合。
- 没有 `Linux`、`Sony`、`version`、`copyright`、`SABIN`、`SSBOOT`、构建主机名或日期。
- 没有 ELF 的 `.comment` / `.rodata` 版本段，因为根本不是 ELF。

### 4.5 未压缩、未加密

- 熵只有 **6.32 / 6.35 bit/byte**；gzip/xz/bzip2/lz4/zstd 的典型值在 7.9 以上。
- 0x00 占比 19% / 18.6%，0xFF 占比 4%，压缩/加密数据不会保留这种分布。
- 文件内部存在约 **1,504 字节的重复块**，相邻块相似度 92.5%–95.2%（`0xEA0`、`0x14D0`、`0x1AB0`、`0x2090` 起）；压缩流不会保留这种周期性明文结构。
- 没有匹配 gzip/xz/bzip2/lz4/zstd/lzo/cramfs/squashfs/ELF/uImage/FIT/ARM zImage/Android boot 任一魔数。
- 结论：**明文、未压缩、未加密**，是结构化的二进制表/配置。

### 4.6 与 idt_cam / sa_dfdet 同族

- `idt_cam.bin`（176,528 B）使用完全相同的 “B4” 容器、同一 `0x682` 常量、同一 `0x48000` 基址指针表。
- `ssboot.bin` 与 `ssboot_any.bin` 去掉头部后逐字节比较：**9,036 / 9,524 字节相同，相似度 94.88%，最长连续相同段 1,444 字节**。
- `ssboot.bin` 载荷 vs `idt_cam.bin` 载荷：相似度 32.86%，最长连续相同段 177 字节。
- 三个文件共享同一段 48 字节序列（`0f 90 cd af 4e 95 de 1e eb 60 ec 61 ...`），`sa_dfdet.bin` 中也出现。
- 因此它们属于同一个 SABIN 固件家族；`ssboot` 与 `ssboot_any` 是同一镜像的两个变体（可能是“通用版”与非通用版的差别），而不是两个独立程序。

### 4.7 ISA / 代码性质

- 用 Capstone 按 ARM、Thumb、MIPS、SH、M68K、Xtensa 等常见 ISA 反汇编，均未得到连贯函数：没有 ARM 的 `bx lr` / `mov pc, lr`，没有 Thumb 的 `pop {..., pc}` / `bx lr`。
- 少量 `b5c4`（Thumb `push`）候选位于 `0x48A`、`0xFC2`、`0x15F2`、`0x1BD2`、`0x21B2`，但周围是明显的数据表，不是指令流。
- 结论：**不是常规 CPU 可直接执行的代码段**，更可能是某种 DSP/传感器子系统（SABIN = sensor/actuator board?）的启动表、寄存器配置或波形/系数数据，由主 CPU 或驱动按 “B4” 协议下发。具体 ISA / 语义没有在镜像内找到文档化线索，未能进一步确定。

### 4.8 与 vmlinuz / cramfs 的关系

**没有关系。**

- 分区里没有 `vmlinuz` 文件；与内核对应的是根目录的 `vmlinux.bin`。
- `vmlinux.bin` 是**原始 ARM32 Linux 内核**（非压缩、非 uImage/FIT）：起始 `d3 f0 21 e3`（`msr cpsr_c, #0xd3`），内含 `Linux version 3.0.27_nl-rt106+`、`#1 SMP PREEMPT RT Mon Nov 15 03:46:31 JST 2021`、GCC 4.5.1、Sony CE Linux 8.2.6.0、ARMv7。
- `initrd.img` 是 **ext2** 文件系统（UUID `e41f2e79-9338-42e6-9c6a-74e55e186dab`），不是 cramfs；里面有 `/dev/nflasha3` 节点、内核模块和 NAND BOSS 相关路径。
- 整个分区**没有实际的 cramfs/squashfs 文件系统**；`cramfs` / `squashfs` 魔数只在内核二进制内部作为“支持该文件系统”的代码/字符串出现。
- SSBOOT 两个文件的大小（11 KB / 9.6 KB）、B4 头、明文结构化载荷，都与 4.1 MB 的内核或 cramfs 镜像不匹配。

### 4.9 名称撞车提醒

Linux 内核里也有一个 `kernel/power/ssboot`（Sony 的 snapshot boot，休眠快照启动）。但 SABIN 目录里的 `ssboot.bin` / `ssboot_any.bin`：

- 只有 11 KB / 9.6 KB，不可能是整机内存快照；
- 是 “B4” 私有容器，与内核快照格式无关；
- 与同为 SABIN 的 `idt_cam.bin` 同族。

因此**不要**把这里的 `ssboot` 当成内核 snapshot-boot 镜像；它更可能是 SABIN 子系统（传感器/执行器板）的启动配置/固件表。

## 5. 复现

```sh
cd out
python3 fat12_walk.py        # 生成 tree.txt / manifest.tsv / manifest.json
python3 ssboot_inspect.py    # 生成 ssboot_hex.txt / ssboot_analysis.json
```

产物：

| 文件 | 内容 |
|---|---|
| `fat12_walk.py` | FAT12/BPB/LFN/簇链解析，输出清单 |
| `tree.txt` | 布局信息 + 完整目录树（LFN + 8.3 + 簇 + 偏移 + 大小 + MD5） |

| `manifest.json` | 同上 + 完整簇链 + 镜像元数据 |

| `ssboot_analysis.json` | 熵、字节分布、魔数、字符串、相似度、重复块 |
| `extracted/` | 从镜像中提取的 15 个文件（分析用副本） |

## 6. 局限

- “B4” 头部字段的语义（`+0x08` 变体号、`+0x0C` 长度、`0x682`、`1.9375`）是基于三个同族文件的对照推断，没有公开文档或固件代码验证。
- 未确定载荷的具体 ISA/DSP 类型；只排除了常见 ARM/Thumb/MIPS/SH/M68K/Xtensa 的常规指令流形态。
- 所有时间戳被统一为打包时间，不能用于判断文件来源或版本先后。
